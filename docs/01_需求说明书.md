## 1. 引言

### 1.1 编写目的

本文档旨在明确 Dataspool 系统的功能需求与非功能需求，作为后续概要设计、详细设计及开发实现的基础依据。本文档面向项目经理、系统架构师、开发工程师及测试工程师。

### 1.2 项目背景

随着企业数据规模的持续增长，跨集群、跨系统的数据迁移与同步需求日益突出。现有工具普遍存在以下问题：

- 部署复杂，依赖繁多，难以快速上手；
- 缺乏高可用保障，单点故障导致迁移中断；
- 扩展性不足，无法通过增加节点线性提升迁移速度；
- 监控与可观测性薄弱，迁移过程黑盒化。

Dataspool 旨在构建一个**下一代混合模式数据迁移与编排平台**，解决上述痛点。

### 1.3 文档范围

本文档覆盖 Dataspool Web 应用系统的全部需求，包括集群管理、任务编排、数据迁移执行、监控可观测性等核心模块。

- Dataspool 项目概念文档（Dataspool_项目.docx）
- Raft 共识算法论文（In Search of an Understandable Consensus Algorithm）
- gRPC 官方规范文档

## 2. 项目概述

### 2.1 产品定位

Dataspool 是一个面向企业级用户的**混合模式数据迁移与编排平台**，支持以极简方式部署并按需弹性扩展。其核心理念是"全能节点（All-in-One）"——每个 Dataspool 实例同时承担控制平面（Control Plane）和执行平面（Agent Plane）两种角色，兼顾了单节点的部署简洁性与多节点的高可用及并发扩展能力。

### 2.2 运行模式

系统支持三种运行模式：

**混合模式（推荐）**：每个节点同时运行 Control 和 Agent，适合中小规模生产环境，部署简单，支持多实例并发和高可用。

**纯 Server 模式**：Control 节点与 Agent 节点分离部署，适合大规模生产环境，性能最优。

**独立 CLI 模式**：不启动 HTTP 服务，直接运行单次迁移任务，适合一次性脚本场景。

### 2.3 核心价值

- 极简部署：单二进制文件，零外部依赖即可启动；
- 高可用：内置 Raft 协议，多节点自动选主，消除单点故障；
- 线性扩展：增加节点即可提升并发迁移速度；
- 全场景支持：支持 Elasticsearch、MySQL、MongoDB、文件系统、S3/NFS 等多种数据源；
- 现代化 UI：可视化任务编排与实时监控。

## 3. 用户角色与使用场景

### 3.1 用户角色

| 角色 | 描述 | 主要操作 |
|------|------|----------|
| 系统管理员 | 负责 Dataspool 集群的部署、配置与维护 | 集群配置、节点管理、用户授权 |
| 数据工程师 | 负责定义和执行数据迁移任务 | 创建模板、提交任务、监控进度 |
| 运维人员 | 负责系统运行状态的监控与告警响应 | 查看集群健康状态、查看日志、处理告警 |
| 只读用户 | 具备查看权限，无操作权限 | 查看任务状态、查看报告 |

### 3.2 核心使用场景

**场景 1：Elasticsearch 索引跨集群迁移**

数据工程师需要将生产环境 ES 集群中 3 年的历史日志索引（约 50TB）迁移至归档集群。用户通过 UI 创建迁移任务，指定源端和目标端连接信息，系统自动将索引分片分配给多个 Agent 节点并行执行，实时展示进度，支持断点续传。

**场景 2：快照恢复迁移**

用户将 ES 快照文件存储于 S3/NFS，需要将其恢复至新集群。Dataspool Agent 直接读取快照文件，无需中间转换，实现快照到新集群的高效迁移。

**场景 3：异构数据库迁移**

MySQL 业务数据需迁移至 Elasticsearch 以支持全文检索。通过插件化 Driver 机制，Dataspool 读取 MySQL 数据，经过字段映射转换后写入 ES。

**场景 4：增量文件同步**

企业内部 NFS 上的日志文件需实时同步至对象存储。Agent 通过 Offset Tracking 机制实现断点续传，保证数据不丢失。

## 4. 功能需求

### 4.1 集群管理

**FR-CLU-001 节点注册与发现**
- 系统支持多节点自动发现，通过配置 `peers` 列表实现节点互联。
- 节点启动后自动加入集群，无需人工干预。

**FR-CLU-002 Leader 选举**
- 系统内置 Raft 协议实现 Leader 自动选举。
- 当 Leader 节点故障时，集群在 `election_timeout`（默认 5s）内完成重新选主。
- Leader 节点负责元数据管理（Templates、ILM、Mappings）和任务分发。

**FR-CLU-003 节点健康检查**
- 系统提供节点健康检查接口，定期检测各节点存活状态。
- UI 实时展示每个节点的角色（Leader/Follower）、CPU 使用率、内存使用率、网络 I/O 等指标。

**FR-CLU-004 节点标签（Tags）**
- 支持为节点设置自定义标签（如 `can-access-nfs`、`es-group`）。
- 任务提交时可指定目标 Agent 标签，实现任务路由（如仅将 NFS 任务分配给有 NFS 访问权限的节点）。

### 4.2 任务管理

**FR-TASK-001 任务创建**
- 支持通过 UI 可视化创建迁移任务。
- 支持通过 YAML 配置文件提交任务（兼容 CLI 模式）。
- 任务配置项包括：源端连接、目标端连接、数据过滤条件、字段映射、资源限制等。

**FR-TASK-002 任务分片（Sharding）**
- Leader 节点自动将大任务拆分为多个分片（如按索引名、日期范围、主键范围等）。
- 分片粒度可配置。

**FR-TASK-003 分布式任务抢占**
- 各 Agent 节点通过分布式锁机制竞争任务分片，先抢先得。
- 支持抢占式任务调度，当某 Agent 空闲时自动获取待处理分片。

**FR-TASK-004 任务生命周期管理**
- 任务状态包括：待执行（Pending）、运行中（Running）、暂停（Paused）、已完成（Completed）、失败（Failed）。
- 支持手动暂停、恢复、取消任务。
- 支持任务重试，可配置最大重试次数。

**FR-TASK-005 断点续传**
- 系统在 Agent 级别和文件级别记录迁移进度（Offset Tracking）。
- 当任务因故中断后，重新启动时从上次断点继续，不重复迁移已完成数据。

**FR-TASK-006 资源限制**
- 每个 Agent 支持配置最大并发任务数（`max_concurrent_tasks`）和内存上限（`memory_limit_mb`）。
- 防止迁移任务过度消耗宿主机资源。

### 4.3 数据源支持

**FR-DS-001 Elasticsearch 数据源**
- 支持 ES 5.x / 6.x / 7.x / 8.x 版本。
- 支持按索引名、通配符（`logs-*`）、日期范围等方式筛选数据。
- 支持 Reindex、Scroll API 两种读取方式。

**FR-DS-002 快照数据源（S3/NFS）**
- 支持读取存储在 S3 或 NFS 上的 ES 快照文件。
- 支持将快照直接恢复至目标 ES 集群，无需中间文件转换。

**FR-DS-003 MySQL 数据源（插件）**
- 通过插件化 Driver 支持 MySQL 5.7+ / 8.0+。
- 支持全表扫描和增量（基于 Binlog 或时间戳）两种模式。

**FR-DS-004 MongoDB 数据源（插件）**
- 通过插件化 Driver 支持 MongoDB 4.x / 5.x / 6.x。
- 支持 Collection 级别的全量与增量迁移。

**FR-DS-005 文件系统数据源**
- 支持读取本地文件系统及 NFS 挂载路径上的文件。
- 支持按文件扩展名、路径通配符过滤。

### 4.4 通信层

**FR-COMM-001 内部 gRPC 通信**
- Control 节点与 Agent 节点之间使用 gRPC + HTTP/2 协议通信。
- 采用双向流（Bidirectional Streaming）保持长连接，支持实时推送指令和上报进度。

**FR-COMM-002 外部 API**
- 对外提供 RESTful API 和 gRPC-Web 接口，供 UI 及第三方系统调用。
- 使用 Protobuf 定义接口契约（.proto 文件），保证多语言客户端一致性。

### 4.5 用户界面

**FR-UI-001 集群视图**
- 展示所有节点列表，包括：节点名称、角色、IP 地址、状态、CPU/内存使用率、当前任务数等。
- 支持节点详情展开查看。

**FR-UI-002 任务列表与详情**
- 展示所有任务的列表视图，支持按状态、时间、名称等条件筛选。
- 任务详情页展示任务配置、各分片执行进度、耗时统计、迁移速率等。

**FR-UI-003 实时日志查看**
- 通过 gRPC Stream 实时接收并展示迁移过程中的日志（类似 `tail -f` 效果）。
- 支持日志级别过滤（DEBUG / INFO / WARN / ERROR）。
- 支持日志搜索与下载。

**FR-UI-004 可视化任务编排**
- 提供向导式任务创建流程：选择数据源 → 配置连接 → 设置过滤条件 → 字段映射 → 选择目标 Agent 组 → 提交。
- 支持任务模板的保存与复用。

**FR-UI-005 告警通知**
- 支持配置告警规则（如任务失败、节点离线、迁移速率低于阈值）。
- 支持通过邮件、Webhook（钉钉、企业微信、Slack）发送告警通知。

### 4.6 配置管理

**FR-CONF-001 配置文件**
- 系统通过 YAML 配置文件（`config/dataspool-cluster.yaml`）进行配置管理。
- 支持环境变量覆盖配置文件中的参数。

**FR-CONF-002 热重载**
- 支持部分配置项（如资源限制、标签）的热重载，无需重启进程。

## 5. 非功能需求

### 5.1 性能需求

- 单节点迁移吞吐量不低于 500MB/s（受限于网络带宽和目标端写入能力）。
- 多节点并发迁移时，吞吐量应随节点数线性扩展（理论上 N 节点达到单节点的 N 倍）。
- UI 页面首屏加载时间不超过 3 秒（正常网络环境下）。
- API 接口响应时间（P99）不超过 500ms（不含实际迁移耗时）。

### 5.2 可用性需求

- 集群可用性（Availability）不低于 99.9%（三节点部署情况下）。
- 任务失败时具备自动重试机制，不需要人工干预。
- 断点续传确保节点重启后数据迁移不丢失、不重复。

### 5.3 安全需求

- API 接口需进行身份认证（JWT Token 或 API Key）。
- gRPC 内部通信支持 mTLS 加密。
- 配置文件中的敏感信息（如数据库密码）支持环境变量或 Secret 管理系统注入，不允许明文存储。
- 提供基于角色的访问控制（RBAC）。

### 5.4 可扩展性需求

- 通过插件化 Driver 机制支持新数据源，无需修改核心代码。
- 集群扩容（增加节点）无需停机，新节点加入后自动参与任务分配。

### 5.5 可运维性需求

- 提供标准化的健康检查接口（`/health`、`/ready`）。
- 提供 Prometheus 格式的指标暴露接口（`/metrics`）。
- 提供结构化日志输出（JSON 格式），便于日志采集系统对接。

### 5.6 兼容性需求

- UI 支持主流浏览器（Chrome、Firefox、Safari、Edge 最新两个版本）。
- 后端支持 Linux x86_64 / ARM64 平台。
- 提供 Docker 镜像和 Helm Chart，支持容器化部署。

## 6. 约束与假设

### 6.1 约束

- 后端使用 Rust 语言开发，前端使用 Vue 或 React 框架。
- 序列化协议使用 Protobuf，接口定义通过 .proto 文件管理。
- 高可用依赖 Raft 协议，生产环境推荐至少 3 个节点部署。

### 6.2 假设

- 用户部署环境中各节点之间网络互通，且延迟满足 Raft 协议选举超时要求。
- 源端和目标端数据系统在迁移期间保持可用状态。
- 用户具备基本的数据系统运维能力，了解 ES/MySQL 等系统的基本概念。

## 7. 术语表

| 术语 | 说明 |
|------|------|
| Control Plane | 控制平面，负责集群管理、元数据存储、任务分发 |
| Agent Plane | 执行平面，负责数据读取、转换、写入 |
| Raft | 分布式一致性协议，用于 Leader 选举和日志复制 |
| Shard / 分片 | 将大任务拆分后的最小执行单元 |
| Offset Tracking | 进度追踪机制，记录已迁移数据的位置，支持断点续传 |
| ILM | Index Lifecycle Management，ES 索引生命周期管理 |
| Mapping | ES 索引字段映射定义 |
| Driver | 数据源插件，封装对特定数据系统的读写逻辑 |
| mTLS | 双向 TLS 认证，用于服务间通信加密与身份验证 |
| RBAC | Role-Based Access Control，基于角色的访问控制 |
